## HIGHEST-PRIORITY OPEN RUNTIME GATES

### Switch in-game crash — source fixed, formal Thor gate still open

`SIGSEGV addr 0x28` in `Core::Timing::CoreTiming::UnscheduleEvent` <-
`KHardwareTimer::EnableInterrupt` <- `KThread::Sleep` <- `Svc::Call`.
Also seen as `CoreTiming::Advance` -> `fibonacci_heap::consolidate()` SIGSEGV.
Crashes roughly a minute into play. **Non-deterministic** — one run died at 35 s
while another ran 665 s clean from the identical state.

The old explanation was wrong: DWARF proves the old `Event::handle` lived at
offset `0x28`; the `weak_ptr` control pointer was at `0x18`. The retained stacks
proved an invalid/damaged Fibonacci-heap node but did not prove the simplistic
same-type UAF story. The replacement is structural:

- `Advance()` copies and pops a due event while holding the queue lock, before
  invoking the callback.
- No queue reference or heap handle survives the unlocked callback window.
- A looping event is freshly emplaced only if its sequence remains unchanged.
- `Event` no longer stores a self-referential Boost handle;
  `UnscheduleEvent()` derives the handle from the locked iterator.
- Expired weak events are consumed instead of spinning forever.

New `Event` DWARF size is `0x28` with no member at offset `0x28`. Two important
pins:

- `core_timing.cpp` SHA-256:
  `00d4ec51f7a805659ddf9e354f2c896a95924302353732ad939577df2e904e3e`
- staged Eden adapter SHA-256:
  `8364d38b172e67241942912f47ab45dec0276c42dabcd0603dabaa3b44480763`

Host/native validation is strong: Android Eden built, 100/100 repetitions of

### Volume (fixed)

EmuFusion never requested audio focus, so its tracks sat permanently at a fixed
**~-13 dB** (close to Android's duck attenuation) with the stream volume curve
never applied — while the stock video player on the *same output thread and
speaker* ducked to true silence. `EngineAudioFocus.java` now requests
`AUDIOFOCUS_GAIN` with matching attributes across all three engine paths.
User has confirmed audibly.

Measured and eliminated first: app-side gain, key routing, wrong stream,
per-device routing, vendor policy on USAGE_GAME, MMAP bypass, deep-buffer
output, USAGE_GAME vs USAGE_MEDIA, and an AYN system app force-setting volume.

### Wii U crash (fixed)

`lucent_native_adapter_destroy` called `dlclose()` at session end. `dlclose`
runs `__cxa_finalize`, destroying file-scope `std::thread` globals the engine
never joins; `~std::thread` on a **joinable** thread calls `std::terminate()`.
Fixed by leaving the engine library mapped
(`unified-android/native/lucent_native_adapter_host.c`).

Also fixed alongside: Cemu's `InitializeSurface` used `std::make_unique`, which
constructed the replacement swapchain (and a second `VkSurfaceKHR` on the same
`ANativeWindow`) **before** the assignment destroyed the old one ->
`VK_ERROR_NATIVE_WINDOW_IN_USE_KHR` -> uncaught throw. Now waits for device idle
and retires the old swapchain first. Exception barriers added at every adapter
ABI entry point. `NeedAdditionalBlocks()` fixed — the audio clock had been
running **3.45% fast**.

### Switch exit crash (fixed)

Eden's `ShutdownMainProcess` did `SuspendEmulation(true)` then `CloseServices()`.
Eden's HLE services are guest `KThread`s pinned to `ServiceThreadCore = 3`, so it
parked the very threads it then waited on forever. Intermittent because
`KThread::TrySuspend` declines to park a thread with kernel waiters. Fixed by
closing services **before** suspending, plus 13 teardown-step log markers.
Verified: five consecutive clean exits, same pid, 472-704 ms each.

Two adapter divergences fixed alongside: a session owned by three different
threads (Eden binds a kernel identity per host thread in `thread_local`), and
per-process initialisers re-running per title.

## TRAPS — read before touching anything

### 1. Crashes were invisible until today
Cemu's `ExceptionHandler_Init()` (`Cemu-0.5/src/main.cpp:123`) `sigaction`ed
SIGABRT/SIGSEGV/SIGBUS/SIGTRAP **and six more, process-wide**, to a handler
ending in `_Exit(1)`. Every native crash **anywhere in the process** — Cemu,
Eden, Qt, ART — became a clean exit with **no tombstone**. Now bracketed with
`HostSignalDispositions`. Any pre-2026-08-09 conclusion drawn from missing
tombstones (including "crashes in four unrelated subsystems = heap corruption")
is unreliable.

### 2. Build flags — omitting one silently breaks a whole system
```sh
cd unified-android && LUCENT_INCLUDE_EXPERIMENTAL_CORES=1 \
LUCENT_AUTOSELECT_EXPERIMENTAL_CORES=1 LUCENT_REUSE_QUALIFICATION_CORES=1 \
LUCENT_INCLUDE_PHASE2_PPSSPP=1 LUCENT_REUSE_PHASE2_PPSSPP=1 \

```
- Omit `AUTOSELECT` -> every game launch opens the Play Store. Build looks healthy.
- Omit `PHASE3_CEMU` -> internal Wii U fails closed.

**Always verify before installing:**
```sh
unzip -l <apk> | grep -o 'liblucent_native_adapter_[a-z]*\.so' | sort -u   # cemu, eden, host
unzip -p <apk> assets/engine-qualification-opt-in.json | grep -o '"autoSelect": *[a-z]*'  # true
```

### 3. `adb shell input` CANNOT drive a running game
`AndroidDeviceScanner.scan()` skips `device.isVirtual()`, so injected events
never resolve during gameplay. Menus work; gameplay does not. Use `sendevent` on
`/dev/input/event9` ("Odin Controller"): A=304, B=305, X=307, Y=308, SELECT=314,
START=315, D-pad=544-547.
- Exit a game with a Select **hold** (`314 1`, sleep 1.8, `314 0`). The pause
  menu's "Exit to Lucent" A press leaks into the library and relaunches.
- Cold start needs `am start … -f 0x18000000` (CLEAR_TASK) — the app restores its
  last session. **Do not preserve the old “Cemu is one-title-per-process”
  limitation:** EmuFusion is required to launch consecutive Wii U titles in the
  same process. The `fa0fb663` second-title arena overflow and the exact
  `f35227bf` stale AArch64 JIT-instance-pointer crash are both fixed in
  `f9c36796`; the four-Cemu-plus-one-Eden same-PID Thor sequence passed.
- **Never use `monkey`** — it injects a random event and has launched games.

### 4. Soak verification false-passes — three different ways so far
1. Counting engine log lines: they keep ticking while the guest is frozen.
2. `resumeRequested = false` parks the render loop leaving a static frame with no
   fps samples — a *paused* session looks identical to a hung guest.
3. A verify script's own escape sequence exiting the game, so a "clean run" was
   the app sitting in the library.

A valid run needs **all** of: non-zero fps samples throughout, screenshots that
are not pixel-identical (`ffmpeg -lavfi psnr`; `average:inf` = frozen), a
screenshot proving gameplay is on screen, and a constant pid.
